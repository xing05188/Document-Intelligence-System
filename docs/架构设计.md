## 1. 系统概述

### 1.1 系统定位

文档智能系统是一个基于大语言模型（LLM）的企业级文档处理平台，提供文档理解、文档编辑、实体提取、表格填表等核心能力。系统采用 **多Agent协作架构**，通过工作流编排引擎将不同能力的 Agent 组合以完成复杂的文档处理任务。

### 1.2 核心功能

| 功能模块 | 说明 |
|---------|------|
| 文档理解 | 支持 docx/pdf/txt/md 等多种格式的文档解析与交互式问答 |
| 文档编辑 | 基于自然语言指令对 Word/Excel/文本进行增删改操作 |
| 实体提取 | 从非结构化文档中提取结构化数据为 JSON 格式 |
| 表格填表 | 根据条件筛选 Excel 数据并填入 Word/Excel 模板 |
| 工作流编排 | 支持多步骤管道式文档处理流程的自定义编排 |
| 会话管理 | 多会话支持，保持对话上下文的连续性 |

### 1.3 设计目标

- **准确性**: 基于 LLM 实现高精度的文档理解和数据提取
- **可扩展性**: 支持多种 LLM 提供商切换，Agent 即插即用
- **可靠性**: 完善的错误处理、审计日志和状态机管理
- **安全性**: 支持认证鉴权、密码加密、数据隔离
- **高性能**: 流式输出、连接池管理、文件缓存

### 2.1 分层架构说明

系统采用 **六层架构**，从上到下依次为：

| 层级 | 职责 | 关键组件 |
|------|------|---------|
| **用户交互层** | 提供多终端交互入口 | CLI 界面、Vue3 SPA、REST API |
| **API 网关层** | 请求路由、认证鉴权、统一错误处理 | FastAPI Router、Auth Middleware |
| **服务编排层** | 业务逻辑编排、服务调度 | AgentService、DocumentService |
| **核心引擎层** | 工作流调度、多 Agent 协作、LLM 调用 | Coordinator、Executor、Agent A-D |
| **数据持久化层** | 结构化数据存储与访问 | PostgreSQL、Repository 模式 |
| **基础设施层** | 文件存储、LLM 提供商、文档解析 | Azure Blob、Local FS、OpenAI SDK |

### 2.2 架构决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| API 框架 | FastAPI | 异步支持、自动 OpenAPI 文档、高性能 |
| 前端框架 | Vue 3 + Vite | 轻量、高性能、组合式 API |
| LLM 集成 | LangChain + 自定义 Provider | 统一接口、多提供商切换、流式回调 |
| 数据库 | PostgreSQL (Supabase) | JSONB 支持、行级安全、成熟生态 |
| Agent 模式 | 多 Agent 协作 | 关注点分离、可独立扩展、可测试 |
| 认证方式 | JWT-like HMAC 令牌 | 无状态、简单可审计 |

#### 3.1.1 Agent_A — 文档编辑引擎

- **职责**: 根据自然语言指令编辑文档，支持 DOCX、MD、TXT、XLSX 格式
- **设计要点**:
  - 通过 `instruction_parser` 将自然语言解析为结构化 `ActionPlan`
  - 使用 `capability_matrix` 校验动作与文件类型的兼容性
  - 每种文件类型有独立的 Adapter（docx_adapter、md_adapter 等）
  - 支持 `extract_content`、`replace_text`、`insert_paragraph`、`delete_paragraph` 等原子操作
- **关键文件**: `src/core/agents/agent_a/`

#### 3.1.2 Agent_B — 实体提取引擎

- **职责**: 从非结构化文档（Word/MD/TXT）中提取结构化数据为 JSON
- **设计要点**:
  - 基于 `langextract` 库实现 LLM-based 抽取
  - 支持根据 Excel 模板列自动推断抽取 Schema
  - 大文档自动分块（chunk）处理，合并结果去重
  - 支持自定义字段映射和输出格式
- **关键文件**: `src/core/agents/agent_b.py`

#### 3.1.3 Agent_C — 数据库存储引擎

- **职责**: 将 Agent_B 提取的 JSON 数据持久化到 PostgreSQL
- **设计要点**:
  - 通过 Repository 模式写入 `tasks` 和 `extraction_results` 表
  - 完整的状态机管理（queued → running → succeeded/failed）
  - 支持自动建表和字段映射
  - 嵌入契约 v1 的错误码规范
- **关键文件**: `src/core/agents/agent_c.py`

#### 3.1.4 Agent_D — 表格填表引擎

- **职责**: 根据自然语言筛选条件从 Excel 提取数据，填入 Word/Excel 模板
- **设计要点**:
  - 支持 14 种筛选算子（eq/ne/gt/gte/lt/lte/contains/in/between/regex 等）
  - LLM 将自然语言条件解析为结构化筛选树
  - 支持单表和多表模板填充（docx 和 xlsx）
  - 支持表头映射、聚合计算（sum/avg/count）
- **关键文件**: `src/core/agents/agent_d.py`

#### 3.1.5 DocumentAgent — 文档理解交互 Agent

- **职责**: 围绕已上传文档进行交互式问答和内容理解
- **设计要点**:
  - 文件内容缓存在 Agent 实例中，支持多轮对话
  - 解析器由底层 document_reader 统一管理
  - 对话历史累积，支持追问和深入分析
  - 实例按 session 缓存（`_agent_cache`），避免重复解析
- **关键文件**: `src/core/agents/document_understand_agent.py`

- **Provider 注册机制**: 通过 `langextract.providers.registry.register` 注解实现

- **流式处理**: 支持 SSE（Server-Sent Events）实时推送，前端通过 `useSSE` composable 消费
- **Markdown 过滤**: 可选的 `MarkdownFilterCallback` 滤除格式符号，用于 CLI 输出

## 6. 接口设计规范

### 6.1 REST API 设计原则

- **URL 风格**: RESTful，资源路径使用**复数名词**
- **版本管理**: 无版本前缀（v1），通过响应体中 `error.code` 区分
- **请求体**: 统一使用 JSON
- **响应格式**: 统一包裹在 `{ success, data, error }` 结构中
- **HTTP 方法**: GET(查询)、POST(创建/执行)、PUT(全量更新)、PATCH(部分更新)、DELETE(删除)

**前端消费**: 通过 `useSSE.js` composable 封装 EventSource 连接。

## 7. 安全策略

### 7.1 认证体系

```
┌───────────────────────────────────────────────────────────────┐
│  认证体系                                                      │
│                                                               │
│  ┌─────────────────────┐    ┌──────────────────────────────┐  │
│  │  密码安全            │    │  令牌管理                     │  │
│  │  ● PBKDF2-HMAC-SHA256│    │  ● HMAC-SHA256 签名          │  │
│  │  ● 210000 次迭代     │    │  ● 包含 sub/phone/exp/jti    │  │
│  │  ● 随机 16 字节盐值   │    │  ● 可配置 TTL（默认 7 天）    │  │
│  │  ● Base64URL 编码    │    │  ● SHA256 摘要索引（防碰撞）   │  │
│  └─────────────────────┘    └──────────────────────────────┘  │
│                                                               │
│  ┌────────────────────────────────────────────────────────┐   │
│  │  Axios 拦截器链                                        │   │
│  │  1. request 拦截: 自动附加 Authorization: Bearer token  │   │
│  │  2. response 拦截: 401 时触发登出，统一错误消息提取       │   │
│  └────────────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────────┘
```

### 7.2 数据安全

| 安全维度 | 措施 |
|---------|------|
| **密码存储** | PBKDF2-HMAC-SHA256 + 随机盐值，210000 次迭代 |
| **令牌存储** | 前端仅存 `access_token` 于 localStorage，服务端存 SHA256 摘要 |
| **文件隔离** | 文件按 session_id 隔离存储，路径格式 `workspace/library/{session_id}/{file_hash}_{file_name}` |
| **数据库** | 支持 SSL/TLS 连接（sslmode 配置），连接池凭据最小化 |
| **环境变量** | 敏感信息从 `.env` 文件加载，不硬编码，`.env` 被 `.gitignore` 排除 |
| **输入校验** | FastAPI + Pydantic 自动校验请求参数，拒绝畸形输入 |

### 7.3 认证配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `AUTH_SECRET_KEY` | `change-me-in-production` | **必须修改为强随机字符串** |
| `AUTH_ACCESS_TOKEN_TTL_MINUTES` | 10080 (7天) | 令牌有效期 |
| `AUTH_REQUIRE_LOGIN` | false | 是否强制登录（开发环境可关闭） |

## 8. 性能优化方案

### 8.1 后端优化

| 优化项 | 策略 | 实现方式 |
|--------|------|---------|
| **数据库连接池** | 连接复用 | psycopg_pool.ConnectionPool，默认 max_size=10 |
| **文件缓存** | 避免重复解析 | TaskExecutor._file_cache 字典缓存 |
| **Agent 实例缓存** | Session 级别复用 | `_agent_cache` 全局字典，session_id 为键 |
| **大文档分块** | 避免 Token 超限 | Agent_B 按语义分割（`split_text_semantic_with_offset`） |
| **LLM 流式输出** | 首 Token 延迟优化 | `stream=True` + SSE 推送 |
| **前端 Keep-Alive** | 缓存组件状态 | `<keep-alive>` 包裹 ChatView，避免 WebSocket 重连 |
| **前端数据缓存** | 减少 API 请求 | localStorage 缓存会话列表和消息历史 |

### 8.2 连接池配置

```python
# db/connection.py 核心配置
_pool = ConnectionPool(
    conninfo=conninfo,
    min_size=1,         # 最小空闲连接数
    max_size=10,        # 最大连接数（可配置 DB_POOL_MAX）
)
```

### 8.3 缓存策略

```
┌────────────────────────────────────────────────────────────────┐
│  缓存层级                          TTL / 策略                   │
│                                                                  │
│  1. Agent 实例缓存 (进程级)          Session 生命周期              │
│     _agent_cache[session_id]                                     │
│                                                                  │
│  2. 文件内容缓存 (进程级)            工作流执行期间                 │
│     _file_cache[file_path] → content                              │
│                                                                  │
│  3. 前端 localStorage 缓存          生命周期（覆盖式更新）          │
│     doc_sessions → 会话列表                                      │
│     doc_messages_{sid} → 消息历史                                 │
│                                                                  │
│  4. Azure Blob CDN (可选)           云存储提供缓存                │
└────────────────────────────────────────────────────────────────┘
```

### 8.4 大文档处理策略

对于超过 LLM 上下文窗口的大文档：

1. **语义分块**: Agent_B 使用 `split_text_semantic_with_offset()` 按段落/句子边界分割
2. **并行提取**: 使用 `ThreadPoolExecutor` 并行处理多个块
3. **结果合并**: 去重 + 合并为完整 JSON 输出
4. **增量处理**: 每处理一定数量块后回调进度通知
